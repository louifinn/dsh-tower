The component axis answers one question for every config key: may a user turn it
off, and if so, must that switch be a component? Four classes cover every key, so
"should this be a component?" is a table lookup rather than a judgement call.

| Class | Meaning |
|---|---|
| `core` | Removing it breaks the Tower contract. It is never a switch. |
| `optional-component` | A capability whose off state leaves the rest of Tower intact. It must be a user-visible switch with a documented fallback. |
| `optional-config` | A tuning knob, not a capability. It stays in the config form and never hides a component. |
| `forbidden-to-disable` | The host, the health contract, the recovery escape, the review contract and the merge gates. No group, row or boolean key may turn it off. |
