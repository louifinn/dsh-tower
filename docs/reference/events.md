# Tower events

> Generated by `npm run docs:generate:events` from `domain/events.js`. Do not edit by hand.

Tower emits process-local Cordis events after successful tool calls (mutations and read-only tools), so
other plugins can observe a repository without polling. This release defines 26 process-local events:
5 stable domain events and 21 deprecated tool-shaped
aliases. Events are **not** sent over the network and carry no telemetry.

## Domain events (stable)

Domain events describe what changed, not which tool ran. They are emitted only after the state write
succeeds, so `revision` is the revision a reader can load back from `state.json`; a failed tool emits
no domain event. `at` is the transition timestamp in epoch milliseconds. `state.json` stays
authoritative: these events are an observation channel, not an event-sourced log, and are never
replayed.

| Event | Payload | Emitted after |
|---|---|---|
| `tower.mission.planned` | `{ missionId, revision, at }` | tower_plan persisted one or more new missions |
| `tower.mission.completed` | `{ missionId, revision, at }` | tower_complete recorded a completion report (or tower_mission set status "completed") |
| `tower.mission.reviewed` | `{ missionId, revision, at }` | tower_review recorded a verdict for the mission branch |
| `tower.mission.merged` | `{ missionId, revision, at, commit }` | tower_merge recorded the merge commit that landed the mission branch |
| `tower.mission.abandoned` | `{ missionId, revision, at }` | a mission transitioned to "abandoned" |

```js
ctx.on('tower.mission.merged', ({ missionId, revision, at, commit }) => {
  // the merge is already durable; commit is the merge commit that landed
})
```

## Tool-shaped aliases (deprecated)

The older `tower/<tool>` events are kept for one minor release as a **deprecated** alias for the
tool-shaped observation channel; prefer the domain events above and expect the alias to be removed in
the next minor. They carry `{ tool, repoRoot, value }`, fire after a successful tool call, and never
fail a tool when a listener throws. For `tower_merge` the alias also fires for a gate failure whose
`value.ok` is false.

| Event | Emitted after |
|---|---|
| `tower/init` | `tower_init` created/re-anchored state or adopted the roster (`value.op`) |
| `tower/plan` | `tower_plan` created missions |
| `tower/mission` | `tower_mission` changed one mission |
| `tower/spawn` | `tower_spawn` recorded a worker/reviewer |
| `tower/complete` | `tower_complete` recorded a completion report |
| `tower/review` | `tower_review` recorded a verdict |
| `tower/merge` | `tower_merge` returned (including gate failures; inspect `value.ok`) |
| `tower/rebase` | `tower_rebase` returned |
| `tower/teardown` | `tower_teardown` removed worktrees |
| `tower/finding` | `tower_finding` reported, listed or updated findings |
| `tower/send` | `tower_send` persisted a message |
| `tower/inbox` | `tower_inbox` acknowledged messages |
| `tower/interrupt` | `tower_interrupt` stopped a live agent |
| `tower/inspect` | `tower_inspect` rendered a read-only view (`value.view`) |
| `tower/recover` | `tower_recover` inspected or cleared a stale state lock |
| `tower/test` | `tower_test` ran discovery |
| `tower/batch` | `tower_batch` created, inspected or closed a batch |
| `tower/resource` | `tower_resource` acquired/released/inspected leases |
| `tower/import` | `tower_import` stored a legacy snapshot or mapped legacy ids (`value.op`-shaped result) |
| `tower/mode` | `tower_mode` read, entered, left or took over the session stance (`value.mode`, `value.action`, actor/reason in `value`) |
| `tower/reload` | `tower_reload` returned a reload schedule/result |

```js
ctx.on('tower/merge', (payload) => {
  // deprecated: prefer tower.mission.merged
  // payload.tool, payload.repoRoot, payload.value (the tool's JSON result)
})
```

For a durable audit trail use `<git-common-dir>/dsh-tower/activity.jsonl` and `MISSIONS.md` instead;
events are process-local and are not replayed.
